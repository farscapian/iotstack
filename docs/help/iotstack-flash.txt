iotstack flash -- Serial flash tool for device setup and recovery

Flashes firmware over USB/serial when OTA is unavailable or for initial setup.
Fresh devices get recovery and production partitions; existing devices can receive
an OTA-style update over serial.

Usage:
  iotstack flash <device> [tty-device] [options]
  iotstack flash failsafe [tty-device|role]

Arguments:
  <device>        Device role (e.g., bleproxy, mmwave, threadrouter)
  failsafe        Flash failsafe image via serial
  [tty-device]    Serial device (e.g., /dev/ttyACM0). Omitted: auto-pick
                  from NVS device_role on USB ports, or the only port with
                  a matching chip variant (e.g. matrixdisplay = esp32s3).
                  New/unprovisioned devices need an explicit tty.
  [role]          Production role for dual-flash (e.g., mmwave, bleproxy)

Options:
  --ota-only      Skip failsafe flash, only OTA production (device already
                  has recovery)
  --on-flash-verify
                  Compare firmware by reading flash over USB (slower, more
                  thorough). Default uses runtime mDNS config_hash (same as
                  iotstack devices / iotstack failsafe).
  --erase         Wipe flash partitions then reflash (skip hash comparison)

Role-specific options (e.g. matrixdisplay HUB75 NVS layout):

  iotstack help <role>              e.g. iotstack help matrixdisplay
  iotstack flash <role> help        same file for flash / update / reassign

NVS secrets (WiFi, OTA password, API key, matrix layout, etc.):
  iotstack prefers updating NVS over the network -- switch to failsafe, then
  call the update_nvs_secrets API service on failsafe-<mac>.local. USB
  (write-nvs-secrets.sh / esptool) is used only when failsafe is not yet on
  WiFi (typical first serial provision) or the API is unavailable.

Smart flash (default):
  Assessment compares runtime config_hash from mDNS (fast). Production OTA
  is skipped when the running firmware matches the compiled build. Serial
  erase runs only when the on-device partition table or failsafe image
  differs from the current build.

  Use --on-flash-verify to compare by reading the full production and
  failsafe partitions over USB instead (adds ~1-2 minutes but verifies
  what is actually written to flash).

Examples:
  iotstack flash bleproxy /dev/ttyUSB0           # Smart setup (recovery + prod)
  iotstack flash failsafe mmwave                 # Dual-flash: failsafe + mmwave
  iotstack flash failsafe /dev/ttyUSB0           # Failsafe image only
  iotstack flash mmwave /dev/ttyACM0 --ota-only  # Skip recovery, OTA prod only
  iotstack flash matrixdisplay help              # Role-specific flash options
  iotstack flash threadrouter                    # Auto-detect all USB devices

For detailed help including architecture and timing, see:
