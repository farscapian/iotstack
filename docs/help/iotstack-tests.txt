iotstack tests -- Overnight integration test runner

Runs scripted end-to-end tests against USB-connected ESP32 boards. Automatically
maps /dev/ttyACM* ports to chip variants (esp32c6 vs esp32s3) using esptool
chip-id, so you can leave a C6 and an S3 plugged in simultaneously.

Usage:
  iotstack tests list
  iotstack tests ports
  iotstack tests run [options] [test...]

Arguments:
  test              Test id (0, 20), numeric prefix (00), or slug (flash-bleproxy).
                    Omit to run the full suite in order.

Options:
  --tty <device>    Pin a port (chip auto-detected; sets C6 or S3 override)
  --iterations <n>  Repeat the suite N times (default: 1)
  --stop-on-failure Stop after the first failing test
  --verbose         Pass -v to iotstack subcommands

Environment (~/.iotstack/.env):
  IOTSTACK_TEST_TTY_C6=/dev/ttyACM0   Optional override for ESP32-C6
  IOTSTACK_TEST_TTY_S3=/dev/ttyACM1   Optional override for ESP32-S3

Role -> chip mapping (from iotstack roles / YAML variant):
  esp32c6: bleproxy, mmwave, threadrouter, bootstrap, ledlightstrip-c6-thread
  esp32s3: ledlightstrip-s3-wifi, sendspin, silentnotify, matrixdisplay

Test suites (regression gate -- hardware-validated builds only):
  00-06  ESP32-C6 bleproxy: flash / verify / update (delta,force) / list / bootstrap list
  10-14  ESP32-C6 boot-partition toggle + bootstrap flash/reassign
  15-16  Compile skip via iotstack flash (hit/miss, build_info.json config_hash)

  Cases for not-yet-hardware-validated builds (mmwave, ledlightstrip-c6-thread,
  ledlightstrip-s3-wifi, silentnotify, matrixdisplay) were pruned. Re-add a build's
  cases only once it is proven on hardware -- the suite is meant to stay a trusted
  regression gate for validated builds, so a fresh agent can rely on green == no
  regression. Pruned cases remain in git history to rewrite from.

Examples:
  iotstack tests ports
  iotstack tests run
  iotstack tests run --iterations 3
  iotstack tests run 0
  iotstack tests run 00-flash-bleproxy
  iotstack tests run 13-update-dry-run
  iotstack tests run 15-compile-cache-hit-bleproxy
  iotstack tests run 16-compile-cache-miss-external-component
  iotstack tests run                # full validated-build suite, in order

Layout:
  tests/cases/<slug>/run.sh                         test script
  tests/cases/<slug>/iotstack-<slug>.log            symlink -> ~/.iotstack/logs/

Logs:
  ~/.iotstack/logs/tests/run_<timestamp>.log        test runner summary
  ~/.iotstack/logs/iotstack-<case-slug>.log         per test case (--log-id)
  ~/.iotstack/logs/esp32_device.log                 serial during flash

Every test case passes --log-id=<case-slug> to iotstack (implies --create-log
and -v). The runner refreshes the per-case log symlink before each run. Disable
logging with IOTSTACK_TEST_LOG_ID=0. Quiet mode is off while logging.

State: ~/.iotstack/artifacts/test-state.env (per-role MAC cache)
Ports: ~/.iotstack/artifacts/serial-port-map.env (last scan)

Overnight (C6 plugged in -- suite is currently C6/bleproxy only):
  iotstack tests run --iterations 5 2>&1 | tee ~/iotstack-overnight.log

Bootstrap firmware is compiled per chip variant (yamls/.iotstack-bootstrap-esp32c6.yaml,
etc.) with separate build directories under yamls/.esphome/build/.
`iotstack flash` detects the chip on each /dev/ttyACM* port and substitutes the
matching profile before compile.
