iotstack flash — Additional Documentation

Extended reference for iotstack flash: dual-partition layout, recovery vs
production firmware, and serial flashing workflows.

Dual-Partition OTA Architecture
================================

Fresh devices need to be set up with a dual-partition layout:

  ┌──────────────────────────────────┐
  │ ESP32 Flash Memory Layout         │
  ├──────────────────────────────────┤
  │ Recovery Partition (read-only)   │ ← Fallback if production fails
  │ ├─ recovery.yaml firmware        │
  │ └─ Always available for failsafe │
  ├──────────────────────────────────┤
  │ Production Partition (active)    │ ← Current device firmware
  │ ├─ Your role (bleproxy, etc)     │
  │ └─ Updated via OTA               │
  ├──────────────────────────────────┤
  │ NVS (Non-Volatile Storage)       │ ← Device secrets (encrypted)
  │ └─ OTA password, WiFi creds      │
  └──────────────────────────────────┘

The failsafe partition holds a universal recovery.yaml firmware that all
devices use. It can't be bricked because production firmware goes to a
separate partition. If production firmware fails, the device can always boot
into failsafe for troubleshooting.


Firmware Assessment
===================

By default, iotstack flash compares the device's runtime config_hash from
mDNS against the compiled build cache — the same hash shown by
`iotstack devices` and `iotstack failsafe`. This is fast (seconds) and
skips OTA when the running firmware already matches.

Pass `--on-flash-verify` to read the production and failsafe partitions
over USB and compare full image MD5 sums instead. That is slower (~1–2
minutes) but confirms what is physically on the flash chip, even when the
device is not on WiFi.


Serial Flash Timing
===================

Fresh device setup is slow but done only once:
  - Serial flash (recovery): ~5-10 minutes (depends on USB speed)
  - Boot and OTA (production): ~2-3 minutes
  - Total: ~10-15 minutes for initial setup

Subsequent updates use OTA (much faster):
  iotstack update bleproxy          # ~30 seconds per device


Auto-Detection of USB Devices
=============================

When you don't specify a tty device, iotstack searches for connected USB
devices:

  iotstack flash bleproxy           # Auto-detect first USB device
  iotstack flash failsafe mmwave    # Auto-detect all USB devices

This only works when:
  - Exactly one USB device is connected (for single flash)
  - Any number for failsafe multi-flash (devices queued as they appear)

For explicit control, always specify the device:
  iotstack flash bleproxy /dev/ttyUSB0


Recovery Mode
=============

Use failsafe mode when:
  - Device firmware is corrupted or won't boot
  - You need to reflash from scratch
  - Device is bricked and OTA isn't responsive

Recovery workflow:
  1. Connect device via USB
  2. Run: iotstack flash failsafe /dev/ttyUSB0
  3. Device boots into failsafe partition
  4. Run: iotstack update <role> (OTA the production firmware)
  5. Device boots into production

The failsafe partition (recovery.yaml) is read-only and shared by all devices,
so it's nearly impossible to brick a device—you can always reflash via serial.
