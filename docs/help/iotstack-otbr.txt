iotstack otbr -- OpenThread Border Router provisioning

Provision Raspberry Pi OTBR devices, Incus test VMs, and bare-metal snap/Docker
installations. Runtime data (cache, logs, artifacts) lives in ~/.iotstack/otbr/.

Usage:
  iotstack otbr <command> [args]
  iotstack -env=<name>.env otbr <command>   # use an alternate environment

Commands:
  setup             One-time setup (apt packages, esptool, incus)
  vm x64            Incus VM test (native x86_64)
  vm arm64          Incus VM (arm64)
  flash             Flash Ubuntu Server 26.04 to SD card (/dev/sdX)
  docker            Docker bare-metal provisioner
  snap              Snap bare-metal provisioner
  snap stop         Gracefully leave the Thread network and stop the local OTBR snap
  logs [-f] <host>  Remote logs over SSH (cloud-init, firstboot, OTBR snap)
  shutdown <host>   Graceful shutdown of a remote OTBR device
  restart <host>    Reboot a remote OTBR device
  help              Show this help

Configuration:
  Settings (OTBR_HOSTNAME, snap channels, MQTT, etc.) live in
  ~/.iotstack/environments/default.env -- see docs/.env.example. WiFi and
  Thread network secrets come from the pass store, seeded by setup.sh:
    pass edit iotstack/default/common/wifi_ssid
    pass edit iotstack/default/common/wifi_password
    pass edit iotstack/default/common/thread_tlv
  If pass also holds a real ha_url and ha_token, vm/flash/docker/snap first check
  the Thread dataset against Home Assistant's and abort on a mismatch
  (SKIP_HA_THREAD_VERIFY=1 to bypass).

Examples:
  iotstack otbr setup
  iotstack otbr flash /dev/sdb
  iotstack otbr flash --hostname=otbr-kitchen /dev/sdb
  iotstack otbr logs -f otbr-kitchen
  iotstack otbr vm x64
  iotstack otbr snap
  iotstack otbr snap stop

See otbr/README.md for full documentation.
